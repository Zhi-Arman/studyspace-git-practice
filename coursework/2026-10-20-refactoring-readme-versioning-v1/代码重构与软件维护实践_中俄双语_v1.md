## 1 数据约定与重构思路 / Данные и подход

每条记录为五项元组：名、姓、部门、未使用休假天数、病假天数。f 使用下标 3，g 使用下标 4；均要求部门相同且对应天数大于 0，返回以一个空格连接的姓名列表。

Каждая запись — кортеж из пяти полей: имя, фамилия, отдел, неиспользованные отпускные дни, больничные дни. f проверяет поле 3, g — поле 4. Отдел должен совпадать, число дней должно быть больше нуля; результат — список имён и фамилий с одним пробелом.

原代码问题是命名不清、筛选与姓名拼接重复，以及数字下标含义不明。重构提取公共筛选函数、命名字段常量，使用清晰业务名称，并通过别名保留 f 和 g。返回顺序、重复姓名、空列表和严格大于零的条件保持不变；不修改输入，也不额外增加数据校验规则。

Устранены неясные имена, повторение логики и числовые индексы без пояснений. Общая функция и константы обеспечивают DRY; псевдонимы сохраняют вызовы f и g. Порядок, повторы, пустой результат и условие больше нуля сохранены. Вход не изменяется; новые правила проверки не добавлены.

## 1 重构后的代码 / Код после рефакторинга

文件 / Файл: code/employees_refactored.py。公共函数说明了输入、筛选规则和返回值；两个业务函数复用同一个筛选实现。

Docstring описывают вход, условие отбора и результат. Обе функции используют одну общую реализацию отбора.

```python
"""Filter employee tuples while preserving the classroom code's behavior."""

from collections.abc import Iterable

EmployeeRecord = tuple[str, str, str, int, int]
FIRST_NAME = 0
LAST_NAME = 1
DEPARTMENT = 2
VACATION_DAYS = 3
SICK_DAYS = 4


def _names_with_positive_days(
    employees: Iterable[EmployeeRecord], department: str, day_index: int
) -> list[str]:
    """Return matching full names in input order, including duplicates."""
    return [
        employee[FIRST_NAME] + " " + employee[LAST_NAME]
        for employee in employees
        if employee[DEPARTMENT] == department and employee[day_index] > 0
    ]


def employees_with_unused_vacation(
    employees: Iterable[EmployeeRecord], department: str
) -> list[str]:
    """Return full names with unused vacation days greater than zero.

    Args: employees contains (first name, last name, department,
        unused vacation days, sick days); department is an exact match.
    Returns: names joined by one space; input order and duplicates kept.
    """
    return _names_with_positive_days(employees, department, VACATION_DAYS)


def employees_with_sick_leave(
    employees: Iterable[EmployeeRecord], department: str
) -> list[str]:
    """Return full names with recorded sick days greater than zero.

    Args: employees uses the same five-field tuple format;
        department is compared exactly, including letter case.
    Returns: ordered full names; an empty list when nothing matches.
    """
    return _names_with_positive_days(employees, department, SICK_DAYS)


# Keep the original calling interface available.
f = employees_with_unused_vacation
g = employees_with_sick_leave
```

## 2 重构前的测试 / Тесты перед рефакторингом

测试先固定原有可观察行为，作为重构的参照。修改后运行同一组测试，可以发现字段选错、条件变化、顺序或姓名格式变化等回归。两个测试覆盖休假与病假两个分支，并包含零值、负值、其他部门和重复姓名；有限测试不能证明所有输入都正确。

Тесты сначала фиксируют наблюдаемое поведение исходной программы. Повторный запуск выявляет регрессии: неверное поле, изменение условия, порядка или формата имени. Два теста проверяют отпуск и больничные, включая нули, отрицательные значения, другой отдел и повтор имени. Конечный набор тестов не доказывает корректность для всех входов.

文件 / Файл: code/test_employees.py。EMPLOYEE_MODULE 仅用于选择原代码或重构代码，不改变断言。

EMPLOYEE_MODULE выбирает исходный или изменённый модуль; проверки остаются одинаковыми.

```python
"""Two characterization tests that can run before and after refactoring."""

import importlib
import os
import unittest

employee_module = importlib.import_module(
    os.environ.get("EMPLOYEE_MODULE", "employees_refactored")
)


class EmployeeFilterTests(unittest.TestCase):
    def setUp(self):
        self.employees = [
            ("Anna", "Ivanova", "IT", 5, 0),
            ("Ivan", "Petrov", "IT", 0, 2),
            ("Olga", "Sidorova", "HR", 7, 3),
            ("Petr", "Orlov", "IT", -1, 0),
            ("Maria", "Volkova", "IT", 1, -2),
            ("Anna", "Ivanova", "IT", 5, 0),
        ]

    def test_vacation_filters_department_and_positive_days(self):
        self.assertEqual(
            employee_module.f(self.employees, "IT"),
            ["Anna Ivanova", "Maria Volkova", "Anna Ivanova"],
        )

    def test_sick_leave_uses_sick_days_instead_of_vacation(self):
        self.assertEqual(
            employee_module.g(self.employees, "IT"),
            ["Ivan Petrov"],
        )


if __name__ == "__main__":
    unittest.main()
```

## 3 修改的部分 / Внесённые изменения

### 3.3 修改前后说明 / Сравнение до и после

1. 函数命名。原来的 f 和 g 改为 employees_with_unused_vacation 和 employees_with_sick_leave，名称直接表达休假和病假筛选用途。末尾保留 f、g 别名，因此原调用仍可运行。

Имена функций. Вместо f и g используются employees_with_unused_vacation и employees_with_sick_leave, явно описывающие назначение. Псевдонимы f и g сохраняют прежние вызовы.

2. 变量命名。l、t、x 分别改为 employees、department、employee。临时列表 r 及 append 循环改为直接返回列表推导式。

Имена переменных. l, t и x заменены на employees, department и employee. Временный список r и цикл с append заменены возвратом спискового включения.

3. 字段下标。原来直接使用 0、1、2、3、4，现在分别命名为 FIRST_NAME、LAST_NAME、DEPARTMENT、VACATION_DAYS、SICK_DAYS，明确每个字段的含义。

Индексы полей. Вместо чисел 0, 1, 2, 3, 4 введены FIRST_NAME, LAST_NAME, DEPARTMENT, VACATION_DAYS и SICK_DAYS, поясняющие значение каждого поля.

4. DRY 去重。原来两个函数重复遍历员工、判断部门和拼接姓名；现在由 _names_with_positive_days 统一处理，两个业务函数只传入对应天数字段。

Принцип DRY. Повторявшиеся обход сотрудников, проверка отдела и сборка имени вынесены в _names_with_positive_days. Две предметные функции передают индекс нужного поля дней.

5. 条件结构。原来的两层 if 合并为“部门相同 and 对应天数大于零”，减少嵌套，同时保持原筛选条件。

Условия. Два вложенных if объединены через and: совпадение отдела и положительное число нужных дней. Вложенность уменьшена, исходное условие сохранено.

6. 接口说明。原来没有 docstring 和类型注解；现在补充五项元组的数据类型、参数含义、返回类型、顺序和重复项等说明，便于理解和维护。

Документация интерфейса. Добавлены docstring и аннотации типов: формат кортежа из пяти полей, параметры, возвращаемый тип, порядок и повторы. Это упрощает понимание и сопровождение.

### 3.4 重构验证结论 / Вывод по проверке

修改集中在命名、结构和文档说明。两个既有测试在修改前后均通过，返回列表与预期值一致；这为已覆盖场景的行为保持提供了证据。空输入、部门不存在等其他场景未纳入这两个测试，不作完整覆盖声明。

## 4 版本号判断 / Выбор номера версии

采用 MAJOR.MINOR.PATCH。以下三项分别以 1.4.2 为起点；将配置文件格式视为用户依赖的公开兼容性约定。

Используется MAJOR.MINOR.PATCH. Каждое изменение отдельно отсчитывается от 1.4.2; формат настроек рассматривается как публичный контракт совместимости.

| 改动 / Изменение | 新版本 / Версия | 理由 / Обоснование |
| --- | --- | --- |
| 修复舍入错误 / Исправлена ошибка округления | 1.4.3 | 兼容的错误修复，递增 PATCH。 / Совместимое исправление, увеличивается PATCH. |
| 增加新报表，原报表仍可用 / Добавлен новый отчёт, прежние работают | 1.5.0 | 新增兼容功能，递增 MINOR，PATCH 清零。 / Новая совместимая функция: MINOR + 1, PATCH = 0. |
| 修改配置格式，旧文件不能使用 / Новый формат настроек, старые файлы не работают | 2.0.0 | 破坏兼容性，递增 MAJOR，其余清零。 / Нарушение совместимости: MAJOR + 1, остальные части = 0. |

依据 / Источник: Semantic Versioning 2.0.0，第 6 至 8 条 / пункты 6–8。
https://semver.org/lang/zh-CN/

若三项按题目顺序连续发布，依次也是 1.4.3 → 1.5.0 → 2.0.0；若三项合并为一次发布，则直接为 2.0.0。

При трёх последовательных выпусках в указанном порядке: 1.4.3 → 1.5.0 → 2.0.0. Если все изменения входят в один выпуск, его версия — 2.0.0.
