| 主要任务 / Главная задача | 找到合适座位并完成预约，查看结果；计划变化时取消本人尚未开始的预约。 | Найти место и забронировать, проверить результат; при изменении планов отменить свою запись до начала. |

| 成功判断 / Признаки успеха | 合法请求产生一个预约 ID；重叠拒绝而相邻及多个非重叠允许；只见本人记录。 | Допустимая заявка даёт один ID; пересечения запрещены, соседние и несколько непересекающихся допустимы; видит только своё. |

| 待访谈问题 / Вопросы интервью | 需真实访谈核对：主要设备、常见学习时段、筛选偏好和误操作场景。 | Проверить в реальном интервью: устройства, обычное время учёбы, фильтры и ошибки действий. |

3 P-002 等待校内核验的新学生

3 P-002 Новый студент ожидающий проверки

| 要素 / Элемент | 中文 | Русский |

| 角色与名称 / Роль и обозначение | 等待校内核验的新学生 | Новый студент ожидающий проверки |

| 使用情境 / Контекст | 首次使用系统，在手机或电脑注册并等待学校管理员核验。 | Первое использование: регистрация с телефона или компьютера и ожидание проверки администратора вуза. |

| 主要任务 / Главная задача | 注册、登录并了解 PENDING/VERIFIED/REJECTED 状态，获得合规预约资格。 | Зарегистрироваться, войти, понять PENDING/VERIFIED/REJECTED и получить допустимое право бронирования. |

| 候选痛点 / Предполагаемая боль | 候选痛点：不知道审核来源和状态含义，把能登录误认为能预约，身份修改后不理解重新核验。 | Предполагаемые затруднения: неизвестны источник и смысл проверки, вход ошибочно понимается как допуск, непонятна повторная проверка после изменения данных. |

| 典型流程 / Порядок действий | 提交必要身份信息 → 注册为 PENDING → 登录只读 → 管理员核验 → VERIFIED 且启用后预约。 | Предоставить необходимые идентификаторы → PENDING → вход для чтения → проверка администратора → бронирование при VERIFIED и активности. |

| 成功判断 / Признаки успеха | 重复学号被拒绝；未核验可只读但不可预约；不存证明影像，来源不明不能冒充核验通过。 | Повтор номера запрещён; без проверки можно читать, но не бронировать; изображения не хранятся, неизвестный источник не даёт подтверждение. |

| 待访谈问题 / Вопросы интервью | OPEN-003：学校认可什么核验来源，谁提供访问授权，哪些身份字段能可靠核对。 | OPEN-003: какой источник признаёт вуз, кто разрешает доступ и какие идентификаторы достоверно проверяются. |

4 P-003 学校资源和身份管理员

4 P-003 Администратор ресурсов и проверки вуза

| 要素 / Элемент | 中文 | Русский |

| 角色与名称 / Роль и обозначение | 学校资源和身份管理员 | Администратор ресурсов и проверки вуза |

| 使用情境 / Контекст | 通过管理界面审核学生、维护房间座位和开放配置，查询预约并处理停用或取消。 | Через административный интерфейс проверяет студентов, ведёт помещения, места и часы, ищет записи и обрабатывает отключение или отмену. |

| 主要任务 / Главная задача | 使账号资格和资源配置可复核，安全处理变更，并获得三项基础预约统计。 | Обеспечить проверяемый допуск и ресурсы, безопасно обрабатывать изменения и получать три базовых показателя бронирований. |

| 候选痛点 / Предполагаемая боль | 候选痛点：权限和核验混淆，停用后预约残留，统计口径不一致，无法追查审核或取消原因。 | Предполагаемые затруднения: путаница прав и проверки, записи после отключения, разные определения показателей, отсутствие оснований проверки или отмены. |

| 典型流程 / Порядок действий | 安全登录 → 复核身份或维护资源 → 带原因处理变更 → 查询记录 → 按统一快照核对统计。 | Безопасный вход → проверка идентификаторов или ресурсов → изменение с причиной → поиск записей → сверка показателей одного снимка. |

| 成功判断 / Признаки успеха | 学生不能越权；身份、角色、启停独立；停用原子取消受影响未结束预约；创建、取消、未结束数不等于到场或使用率。 | Студент не превышает права; проверка, роль и активность независимы; отключение атомарно отменяет затронутые записи; создание, отмена и незавершённость не означают посещение или загрузку. |

| 待访谈问题 / Вопросы интервью | 核对实际管理员职责、核验来源、开放例外操作与统计使用场景；不将管理员画像拆成未经批准的新系统角色。 | Уточнить обязанности, источник проверки, исключения часов и применение статистики; не превращать профиль в новые неутверждённые системные роли. |
