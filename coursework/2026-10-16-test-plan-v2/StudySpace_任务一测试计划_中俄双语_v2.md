## 1. 范围 / Область тестирования

| 编号 / № | 范围内容 / Содержание |
| --- | --- |
| IN-1 | **范围内：**学生注册、登录、角色权限及校内身份人工审核；只有 `ENABLED + STUDENT + VERIFIED` 可预约（FR-001～FR-003、FR-022）。<br>**Включено:** регистрация, вход, права и ручная проверка принадлежности к вузу; бронирование доступно только `ENABLED + STUDENT + VERIFIED` (FR-001–FR-003, FR-022). |
| IN-2 | **范围内：**教室/自习室、单个座位、开放时间的查询与管理（FR-004～FR-006、FR-011～FR-012、FR-017）。<br>**Включено:** просмотр и управление помещениями, отдельными местами и часами работы (FR-004–FR-006, FR-011–FR-012, FR-017). |
| IN-3 | **范围内：**创建、冲突判定与取消预约；每条预约一个座位，同一学生或同一座位的重叠时段拒绝，相邻与非重叠时段允许（FR-007～FR-009、BR-001～BR-005）。<br>**Включено:** создание, проверка конфликтов и отмена; одна запись соответствует одному месту, пересечения студента или места отклоняются, соседние и непересекающиеся интервалы допустимы (FR-007–FR-009, BR-001–BR-005). |
| IN-4 | **范围内：**个人预约记录、管理员操作及基础统计（FR-010、FR-013～FR-016）。<br>**Включено:** личная история, действия администратора и базовая статистика (FR-010, FR-013–FR-016). |
| IN-5 | **范围内：**核心流程的中、俄、英三语界面，以及权限、隐私和事务一致性检查（NFR-003～NFR-004、NFR-006～NFR-007）。<br>**Включено:** основные сценарии интерфейса на китайском, русском и английском; права, приватность и согласованность транзакций (NFR-003–NFR-004, NFR-006–NFR-007). |
| OUT-1 | **范围外：**预约提醒和二维码签到（FR-018、FR-019；未来版本）。<br>**Исключено:** напоминания и регистрация по QR-коду (FR-018, FR-019; будущая версия). |
| OUT-2 | **范围外：**违约记录和资源使用率统计（FR-020、FR-021；未来版本）。<br>**Исключено:** учёт нарушений и статистика использования ресурсов (FR-020, FR-021; будущая версия). |

## 2. 方法 / Подход

| 层级 / Уровень | 工具、自动化与人工工作 / Инструменты, автоматизация и ручная работа |
| --- | --- |
| A-1 单元与服务层 / Модульный и сервисный | 后端计划使用 `pytest`，前端使用 `Vitest`；自动检查资格、时间边界、冲突及组件行为，人工复核需求预期。<br>Для сервера запланирован `pytest`, для клиента — `Vitest`; автоматические проверки прав, границ времени, конфликтов и компонентов, ручная сверка ожидаемого результата с требованиями. |
| A-2 API 与数据库集成 / Интеграция API и БД | 业务 API 实现后，用隔离数据库和合成数据自动验证请求、权限、回滚与并发；分别检查 SQLite 和候选 PostgreSQL 的事务行为，并人工检查异常记录。<br>После реализации бизнес-API автоматические проверки запросов, прав, отката и конкуренции на изолированной БД и синтетических данных; транзакции SQLite и планируемой PostgreSQL проверяются отдельно, журналы ошибок просматриваются вручную. |
| A-3 系统与验收 / Система и приёмка | 通过浏览器执行中俄英核心流程，自动回归可稳定重复的路径；人工检查译文、可用性、隐私及教师验收材料。教师的实际决定另行记录。<br>Браузерные сценарии на трёх языках; устойчивые пути включаются в автоматическую регрессию, перевод, удобство, приватность и материалы для преподавателя проверяются вручную. Его фактическое решение фиксируется отдельно. |

中文：重点边界包括默认 `08:00–22:00`、30 分钟粒度、上海时区的 7 个自然日、最长 24 小时、开始前取消，以及同一座位/学生的并发冲突。24 小时正例只在显式配置全天开放的未来业务日成立；不把默认 14 小时窗口误写为 24 小时开放。

Русский: Ключевые границы: обычное окно `08:00–22:00`, шаг 30 минут, семь календарных дней по времени Шанхая, максимум 24 часа, отмена до начала и конкурентные конфликты места/студента. Положительный пример на 24 часа возможен лишь при явно заданном круглосуточном окне будущего дня; обычное 14-часовое окно не считается круглосуточным.

## 3. 环境 / Среда

| 编号 / № | 测试环境与数据 / Среда и данные |
| --- | --- |
| E-1 | **服务器与前端：**隔离的 FastAPI 后端及 React/TypeScript/Vite 前端；每次记录代码版本、OS、Python/Node 版本、命令和服务地址。<br>**Сервер и клиент:** изолированные FastAPI и React/TypeScript/Vite; для каждого запуска фиксируются версия кода, ОС, версии Python/Node, команды и адреса сервисов. |
| E-2 | **数据库：**开发测试使用独立 SQLite；PostgreSQL 是待验证的部署候选，迁移与并发结果须单独记录。<br>**БД:** отдельная SQLite для разработки; PostgreSQL — кандидат для развёртывания, миграция и конкуренция документируются отдельно. |
| E-3 | **账号：**合成的待审核学生、已核验学生和管理员账号，分别覆盖可读、可预约和管理权限；不得使用真实学生凭据或默认管理员密码。<br>**Учётные записи:** синтетические ожидающий и проверенный студенты, а также администратор для проверки чтения, бронирования и управления; без настоящих учётных данных и пароля администратора по умолчанию. |
| E-4 | **数据与时钟：**隔离的房间、座位、开放窗口和预约样本；使用可控时钟与 `Asia/Shanghai` 业务时区，执行后清理测试数据。<br>**Данные и часы:** изолированные помещения, места, окна и записи; управляемые часы и деловой часовой пояс `Asia/Shanghai`, очистка после прогона. |
| E-5 | **校内核验：**真实可信渠道仍属 OPEN-003；只使用合成核验材料验证流程，不将模拟审核视为真实学校确认。<br>**Проверка вуза:** надёжный реальный источник остаётся OPEN-003; процесс проверяется только на синтетических данных, имитация не считается подтверждением вуза. |

## 5. 入口与出口 / Критерии начала и завершения

下列标准用于**未来执行**，当前均不得视为已满足。 / Следующие критерии относятся к **будущему выполнению**; сейчас они не считаются выполненными.

| 编号 / № | 可测量标准 / Измеримый критерий |
| --- | --- |
| ENTRY-1 | **入口：**本轮纳入的每个 MVP 需求 ID 均有至少 1 个关联 TC、明确的预期结果与评审记录；覆盖率达到 `100%`。<br>**Начало:** каждому включённому требованию MVP соответствует минимум один TC, ожидаемый результат и запись рецензирования; покрытие `100%`. |
| ENTRY-2 | **入口：**目标构建可启动，健康/就绪检查符合该环境预期；隔离数据库、可控时钟，以及至少 1 个待审核学生、1 个已核验学生、1 个管理员、2 个座位的合成数据可用。<br>**Начало:** целевая сборка запускается, проверки состояния соответствуют среде; доступны изолированная БД, управляемые часы и синтетические данные минимум для одного ожидающего студента, одного проверенного, одного администратора и двух мест. |
| EXIT-1 | **出口：**双方确认的 MVP 必测 TC 执行率与通过率均为 `100%`；必测项中 `NOT_RUN`、`BLOCKED`、`FAIL` 均为 `0`。<br>**Завершение:** выполнение и прохождение согласованного обязательного набора MVP TC составляют `100%`; среди них `NOT_RUN`, `BLOCKED` и `FAIL` равны `0`. |
| EXIT-2 | **出口：**未关闭的阻断级或严重级缺陷为 `0`；已修复缺陷均有对应重测记录。<br>**Завершение:** открытых блокирующих или серьёзных дефектов `0`; для каждого исправленного дефекта есть запись повторной проверки. |
| EXIT-3 | **出口：**`100%` 已执行用例记录版本、环境、执行人、日期、预期/实际及证据；形成追溯和总结报告，并记录教师的实际验收决定。<br>**Завершение:** для `100%` выполненных кейсов записаны версия, среда, исполнитель, дата, ожидаемое/фактическое и свидетельство; подготовлены трассировка и отчёт, фактическое решение преподавателя зафиксировано. |

## 6. 风险与措施 / Риски и меры

| 编号 / № | 风险 / Риск | 措施 / Мера |
| --- | --- | --- |
| R-1 | 真实校内身份核验渠道未落实，模拟审核可能被误当成真实通过（OPEN-003）。<br>Источник настоящей проверки вуза не определён; имитацию можно ошибочно принять за подтверждение (OPEN-003). | 仅以合成数据测流程；未知来源保持 fail closed；取得可信渠道并补测后才声称真实核验。<br>Проверять процесс только на синтетических данных, при неизвестном источнике не выдавать допуск; реальную проверку заявлять лишь после получения надёжного канала и дополнительных тестов. |
| R-2 | SQLite 与 PostgreSQL 的锁和并发行为可能不同，造成重复预约或错误成功。<br>Различия блокировок и конкуренции SQLite и PostgreSQL могут привести к двойной записи или ложному успеху. | 在两种数据库分别执行同座位、同学生并发及回滚测试；检查服务端事务，保留失败证据。<br>Отдельно проверить на обеих БД конкурентные запросы к одному месту и одному студенту, а также откат; проверить серверную транзакцию и сохранить свидетельства ошибок. |
| R-3 | 教师验收条件、课程期限和评分细节未确认（OPEN-008），可能导致提交口径偏差。<br>Условия приёмки, срок и оценивание преподавателя не уточнены (OPEN-008), что может изменить состав сдачи. | 提前核对并记录教师要求，更新必测清单及出口标准；取得实际决定前保持 DRAFT/未验收。<br>Заранее уточнить и записать требования преподавателя, обновить обязательные кейсы и критерии завершения; до фактического решения сохранять статус черновика и отсутствие приёмки. |
