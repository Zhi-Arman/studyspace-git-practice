# StudySpace Frontend / 前端 / Клиентская часть

Application / 应用 / Приложение: **0.1.0**. Documents / 文档 / Документы: **0.3.0**. Status / 状态 / Статус: **初始化基础，SRS草稿 / Основа инициализации, черновик SRS**.

## 1. 中文

React、TypeScript、Vite 和 Ant Design 前端基础工程。当前页面展示已澄清的MVP范围、中文/俄语/英语切换，以及真实的后端健康连接状态。正式项目文档仍为中文和俄语两个版本，SRS仍是草稿。尚未实现注册、校内身份验证、登录、资源查询、预约或管理员业务。

MVP预约单位为教室或自习室内的单个座位：每次一个座位，同一学生的预约时段不得重叠；非重叠时段允许多条预约，包括不同未来日期；单次最长24小时。首页只说明这些规则，未实现相应业务或验证规则。

### 1.1 运行

需要 Node.js 22.13 及后续 22.x 版本，或 Node.js 24+，以及 npm。从项目根目录执行：

```sh
[ -e .env ] || cp .env.example .env
cd frontend
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173`。后端需独立运行在 `http://127.0.0.1:8000`，所有 `/api` 请求通过 Vite 转发。项目根目录 `.env` 中的 `API_PROXY_TARGET` 可覆盖代理目标；该值由开发服务器读取，不注入浏览器包。不要将凭据放入任何 `VITE_*` 变量。

### 1.2 验证

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Vitest / Testing Library 测试覆盖健康响应合同、HTTP / 网络 / 超时 / 非法响应、页面连接结果、重试、三语切换、座位范围文案与 StrictMode 取消。它们不验证尚未实现的预约业务。构建产物位于 `dist/`。`npm run preview` 在 `http://127.0.0.1:4173` 预览静态产物；该预览不提供 `/api` 代理，联调应使用 `npm run dev` 或已配置的 Docker Compose 服务。

### 1.3 健康接口与 Docker

`GET /api/v1/health` 必须返回包含 `status: "ok"`、`service: "StudySpace"`、`version: "0.1.0"` 的 JSON。页面进行运行时验证，5 秒后中止请求；健康成功不等于业务验收。

多阶段 `Dockerfile` 使用 Node.js 22 构建，然后由 Nginx 在容器端口 80 提供静态资源。Nginx `/api/` 代理依赖同一 Docker 网络中的 `backend:8000`，`/healthz` 仅检查 Nginx。该配置为可选部署候选；真实运行结果以项目验证记录为准。

## 2. Русский

Основа клиентской части на React, TypeScript, Vite и Ant Design. Страница показывает уточнённый объём MVP, переключение между китайским, русским и английским языками и фактическое состояние соединения с сервером. Официальные документы проекта по-прежнему ведутся на китайском и русском языках; SRS остаётся черновиком. Регистрация, проверка принадлежности к вузу, вход, поиск ресурсов, бронирование и функции администратора пока не реализованы.

Единица бронирования MVP — отдельное место в учебной аудитории или помещении для самостоятельной работы: одно место на бронирование, интервалы одного студента не пересекаются; разрешено несколько непересекающихся бронирований, в том числе на разные будущие даты; длительность не более 24 часов. Главная страница только описывает правила; бизнес-функции и их проверка ещё не реализованы.

### 2.1 Запуск

Требуются Node.js 22.13 и последующие версии 22.x либо Node.js 24+, а также npm. Из корня проекта выполните:

```sh
[ -e .env ] || cp .env.example .env
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Сервер запускается отдельно на `http://127.0.0.1:8000`; Vite перенаправляет все запросы `/api`. Переменная `API_PROXY_TARGET` в корневом файле `.env` позволяет изменить адрес прокси. Она читается сервером разработки и не включается в клиентскую сборку. Не помещайте учётные данные в переменные `VITE_*`.

### 2.2 Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Тесты Vitest / Testing Library проверяют контракт ответа, ошибки HTTP / сети / тайм-аута / формата, отображение состояния, повторную проверку, переключение трёх языков, описание бронирования мест и отмену запроса в StrictMode. Они не проверяют ещё не реализованные бизнес-функции. Результат сборки находится в `dist/`. `npm run preview` показывает статическую сборку по адресу `http://127.0.0.1:4173` без прокси `/api`; для интеграции используйте `npm run dev` или настроенные сервисы Docker Compose.

### 2.3 Проверка работоспособности и Docker

`GET /api/v1/health` должен возвращать JSON с полями `status: "ok"`, `service: "StudySpace"`, `version: "0.1.0"`. Страница проверяет контракт во время выполнения и отменяет запрос через 5 секунд. Успешная проверка не означает приёмку бизнес-функций.

Многоэтапный `Dockerfile` выполняет сборку на Node.js 22, затем Nginx обслуживает статические файлы на порту 80 контейнера. Прокси `/api/` требует сервис `backend:8000` в той же сети Docker; `/healthz` проверяет только Nginx. Это вариант дополнительного развёртывания; фактические результаты приводятся в записи проверки проекта.
