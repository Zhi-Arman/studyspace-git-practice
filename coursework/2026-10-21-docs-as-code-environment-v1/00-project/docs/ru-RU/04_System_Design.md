Это не означает рассмотрения всей SRS, действующей политики вуза, реализации бизнеса или приёмки. Все официальные требования остаются PROPOSED.

## 1 Состояние и объём проектирования

0.3.0 использует подтверждённый MVP одного места и разрешённые стратегии; требования PROPOSED, документ DRAFT. Сейчас есть только главная страница, health/ready/API-документация и подключение. Идентификация, проверка в вузе, места, бронирование, статистика и полный трёхъязычный интерфейс не реализованы. Уточнение правил не доказывает реализацию или приёмку.

## 2 Архитектура и границы

React/TypeScript/Vite/Ant Design вызывает FastAPI по HTTP. Pydantic проверяет ввод, синхронный SQLAlchemy работает через синхронные пути. SQLite для разработки, PostgreSQL для целевого размещения. Alembic до первой сущности, миграция/откат/конкуренция проверяются раздельно. Docker Compose и HTTPS-прокси Caddy выбраны для размещения; домен/площадка неизвестны, развёртывания нет. ADR-0001, ADR-0002 и ADR-0003 сохраняют исторические ID.

## 3 Модули и выбранные стратегии

### 3.1 Идентификация, проверка в вузе и доступ

student_no уникален во всём вузе, full_name используется для ручной проверки. Состояния PENDING, VERIFIED, REJECTED. Ожидающий студент входит и видит состояние, бронирует только VERIFIED, после отказа запрашивает повторную проверку. Необходимый User содержит исходные номер, имя и текущий статус; событие — UserID, состояние, проверяющего, event_at и ссылку/тип источника без копий личности или фото. Источник определяется вузом; реальная платформа и списки ещё не подключены; без источника fail closed, VERIFIED не одобряется. Администратор создаётся будущей явной командой без исходного пароля и самоэскалации; отключение пользователя транзакционно отменяет его незавершённые записи с причиной.

### 3.2 Помещения, места и доступность

Room: кампус, корпус, этаж, имя комнаты, CLASSROOM или STUDY_ROOM. Seat имеет уникальный (room_id,seat_code) и enabled. Вместимость вычисляется по включённым местам, целая комната не бронируется. Достаточен список/сетка, целевые языки — китайский, русский, английский; графический план необязателен. Поиск использует те же правила времени, включения и конфликтов, что запись, и возвращает доступность мест.

### 3.3 Место, непересечение студента, конфликты и отмена

По умолчанию 08:00–22:00 ежедневно, минимум 30 минут, обе границы кратны 30 минутам. start строго>фактического now после блокировок; дата — сегодня–сегодня+6 Asia/Shanghai, семь дней; end-start≤24 часа, без выхода за выбранный день. День D: [D 00:00,(D+1)00:00), конечная полночь означает 24:00 даты D без занятия следующего дня. По умолчанию максимум 14 часов; открытие 00:00–24:00 может дать 24 часа при всех остальных условиях.

Действующие бронирования одного seat не пересекаются в [start,end), соседние допустимы. Одна запись содержит одно место. Неотменённые записи одного user_id конфликтуют при existing.start < new.end AND new.start < existing.end, для одинакового или разного seat. Соседние разрешены, несколько непересекающихся будущих записей в одном/разных днях допустимы, без дневной/будущей квоты количества. DEC-016 заменяет прежнее толкование DEC-004; отмена освобождает только её интервал, остальные записи сохраняются. Владелец отменяет только при фактическом now<start после блокировок, после — администратор с причиной. В одной транзакции проверяются принадлежность, интервал студента, место, часы, время и конфликт. PostgreSQL создание: User→Room→Seat, затем актуальное время и повторная проверка. Закрытие/изменение часов: Room→затронутые Seats по возрастанию ID без User; User-блокировка защищает проверку интервалов одного пользователя без countlimit. Закрытие удаляет только затронутые интервалы, не создаёт новый конфликт User и не берёт User, избегая обратного порядка. Отмена/отключение сначала User, затем Room/Seat. SQLite: BEGIN IMMEDIATE перед актуальным now. Стратегии выбраны, не реализованы/проверены, старый transaction_timestamp недопустим. Тайм-аут не доказанный конфликт, прочие ошибки не все 409. Повторная отмена идемпотентна без новых счётчиков/аудита; проверка перед записью не доказывает корректность.

### 3.4 Управление, закрытие и статистика

Администратор ведёт Room, Seat, часы, правила, состояние и проверки пользователей. Закрытие интервала или отключение комнаты/места в той же транзакции отменяет затронутые незавершённые бронирования с причиной; остальные места сохраняются; освобождается только отменённый интервал, остальные записи не меняются. Отключение пользователя также атомарно.

Статистика отражает создания, отмены и текущие незавершённые записи бизнес-даты, а не присутствие, регистрацию посещения или фактическую загрузку. Все три по дате бронирования D и единому as_of: created_at≤as_of, canceled_at≤as_of, неотменённое end>as_of включая будущее. Истёкшее показано недоступным, не ложным 0. Анализ загрузки отделён от базовых чисел.

### 3.5 Будущие расширения

FR-018–FR-021 — напоминания, QR, нарушения и загрузка, вне критического пути MVP. FR-017 уже относится к MVP, FR-022 добавляет университетскую проверку; ID сохраняются. Расширения требуют отдельного рассмотрения, изображения, данные посещения и внешняя отправка не обещаются.

## 4 Данные, транзакции и миграции

Кандидаты User, IdentityReview, Room, Seat, OpeningSchedule, Reservation, BookingPolicy и AuditEvent не имеют таблиц. Требуется проектировать уникальность student_no, (room_id,seat_code), непересечение студента, конфликт и атомарные отмену/закрытие/отключение аккаунта. Время хранится UTC и показывается Asia/Shanghai, бизнес-дата записи определяется явно.

Alembic до первой сущности. Миграция и откат проверяют схему, данные, внешние/уникальные ключи, время и конкуренцию отдельно на SQLite и PostgreSQL. Ежедневные семь последних копий только для восстановления без внешней отправки; резервирование и тренировка восстановления ещё не реализованы. Подключение не означает успешного переноса.

## 5 API, интерфейс и время

Рабочая основа по-прежнему содержит /api/v1/health, /api/v1/ready и служебную документацию. Для трёх бизнес-точек подготовлены [OpenAPI](../api/openapi.yaml) и [DOC-17](17_API_Contract.md): версия, предложенная защита, общие ошибки, типы, обязательность и примеры. Реализация бизнеса и остальные API полного MVP ещё предстоят. Время передаётся с часовым поясом и нормализуется в UTC, дата определяется Asia/Shanghai. Недопустимое время не округляется молча: интерфейс выбирает границы, сервер отклоняет неверные. Три языка требуют общих ключей, ошибок и сценариев; трёхъязычная стартовая страница не доказывает завершение всех бизнес-сценариев.

## 6 Безопасность, данные и жизненный цикл

Студент видит только свои бронирования/состояние проверки, администратор — минимум. Безопасное хеширование пароля выбирается при дальнейшей безопасности; журналы не содержат пароль, token или фото. User хранит необходимые student_no, full_name, текущий school_identity_status; событие — UserID, состояние, проверяющего, event_at, ссылку/тип источника без копий личности/фото. Источник определяет вуз, без него fail closed. Текущий VERIFIED не истекает со старым событием; номер уникален среди сохраняемых личностей, после очистки новая регистрация снова проверяется.

История 180 дней от завершения(canceled_at либо end), события 180 дней от event_at. Не менее 30 дней отключения и отсутствие незавершённого дают право очистки; необратимый момент=max(отключение+30, все связанные 180 истекли), до этого ограниченная связь, полная анонимизация за 30 не заявляется. Копии ежедневные, семь последних, только восстановление без отправки; после него сначала повторить сроки/очистку, затем открыть. Это разрешённая политика курса без правового заявления. Секреты через среду, .env вне Git.

## 8 Рассмотрение и следующие шаги

Сначала спроектировать состояния проверки, ER мест, интервалы студента, конфликт и транзакции закрытия, затем рассмотреть подготовленный контракт трёх точек перед реализацией и спроектировать три языка. PARTIAL остаются только OPEN-003 источника проверки, OPEN-008 имени/срока/оценивания/формата и OPEN-010 домена/площадки. Принятые стратегии не объявляются неизвестными; показатели испытаний, механизм аутентификации и бизнес-приёмка ещё предстоят.
