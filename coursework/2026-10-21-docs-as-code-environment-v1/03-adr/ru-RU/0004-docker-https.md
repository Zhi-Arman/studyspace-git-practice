## 1 Контекст

Пользователь предпочитает Docker и HTTPS, место размещения неизвестно. DEC-010 и DEC-015 задают направление, OPEN-010 остаётся PARTIAL; выбор архитектуры не означает выполненного размещения.

## 2 Решение

Кандидат использует Docker Compose, Caddy как публичный HTTPS-вход, Nginx для статики, передачу /api в FastAPI и PostgreSQL во внутренней сети. БД, данные приложения и сертификаты сохраняются отдельно; разработка остаётся на SQLite. Домен, сервер, пароли и публичные порты не настроены, настоящие или исходные производственные пароли не задаются.

Текущий compose.yaml — локальный HTTP-каркас, не готовая производственная HTTPS-конфигурация; сборка и запуск контейнеров не проверены. Для размещения отдельно готовятся конфигурация, миграции, восстановление и HTTPS-проверки.

## 3 Предпосылки и проверки

Публичный домен должен указывать на сервер, 80/443 быть доступными, хранилище Caddy — постоянным и доступным для записи. Частные локальные сертификаты требуют доверия клиента и не равны публичным. Сертификаты, DNS и настройки безопасности изменяются только при разрешённом размещении. [Официальное описание Caddy](https://caddyserver.com/docs/automatic-https).

Ворота выпуска включают фактическую сборку, здоровье контейнеров, миграцию/откат PostgreSQL, реальный HTTPS, три языка бизнес-процессов и тестовые свидетельства; выполнение здесь не заявляется.

## 4 Последствия

吕嘉伟 как менеджер координирует сроки/риски, 曹浩然 как тестировщик проектирует проверки миграции/конкуренции, разработка и размещение совместные. Меньше ручных различий среды, больше ответственности за сертификаты и тома. При неизвестных домене/сервере продолжается локальная разработка; конфигурация не заменяет приёмку реального выпуска.
