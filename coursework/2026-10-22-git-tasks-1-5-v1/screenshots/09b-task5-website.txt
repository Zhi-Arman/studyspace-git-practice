任务 5 场景二 内部网站
Задание 5 Сценарий 2 Внутренний сайт

条件 / Условия
每天更新多次。
Обновление несколько раз в день.

选择 / Выбор
GitHub Flow

理由 / Обоснование
1 每项小改动从 main 创建短期分支。
  Для каждого небольшого изменения создаётся короткоживущая ветка от main.
2 开发和测试后提交 Pull Request，经过审查再合并。
  После разработки и тестирования открывается Pull Request;
  слияние выполняется после проверки.
3 主分支保持可发布，按发布流程频繁部署。
  Ветка main остаётся готовой к выпуску;
  развёртывание выполняется часто по принятому процессу.
4 减少长期分支维护，支持小批量、快速反馈。
  Меньше долгоживущих веток, небольшие изменения и быстрая обратная связь.

结论 / Вывод
轻量流程适合频繁更新的内部网站。
GitHub Flow подходит для частых небольших обновлений внутреннего сайта.
