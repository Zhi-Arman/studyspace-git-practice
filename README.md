# StudySpace · 本地自习座位预约

StudySpace · Локальная система бронирования учебных мест

**应用 / Приложение 0.4.0 · 2026-10-23 · 本地课程版 / Локальная учебная версия**

为专注学习找一个座位：查询空间和空闲座位、注册本地账号、预约、查看及取消；管理员维护空间、座位、开放时间、日期例外、用户权限、预约与基础统计。界面中文／俄语／英语即时切换。

Поиск помещения и свободного места, локальная регистрация, бронирование, просмотр и отмена. Администратор управляет ресурсами, расписанием, исключениями, пользователями, записями и статистикой. Интерфейс: китайский, русский, английский.

用户已明确取消真实学校身份验证、服务器和域名要求。当前账号为 **LOCAL_ONLY**，演示资源不代表真实学校；无邮件、学校平台或外部字体依赖。提醒、签到、违约、实际使用率仍属未来范围。

По поручению пользователя реальная проверка вуза, сервер и домен не требуются. Аккаунты **LOCAL_ONLY**, ресурсы демонстрационные; почта, внешние шрифты и вузовские сервисы не нужны. Напоминания, присутствие, нарушения и фактическая загрузка остаются будущими.

## 1 Docker 启动 / Запуск Docker

安装并启动 Docker Desktop，然后在仓库根目录运行 / Запустите Docker Desktop, затем в корне репозитория:

```bash
docker compose up -d --build
```

打开 **http://127.0.0.1:8080/**。首次启动自动迁移 SQLite 并生成两个标明为演示的空间、12个座位；不创建默认账号。可在页面自行注册学生。

Откройте **http://127.0.0.1:8080/**. При первом старте выполняется миграция SQLite и создаются два демонстрационных помещения с 12 местами. Стандартных аккаунтов нет; студента можно зарегистрировать в интерфейсе.

```bash
# 交互创建管理员；密码不会显示 / Создание ADMIN, пароль скрыт
docker compose exec backend .venv/bin/python -m app.cli create-admin --username localadmin --name "Local administrator"
# 查看运行状态 / Состояние
docker compose ps
# 停止，保留数据 / Остановка с сохранением данных
docker compose down
# 如8080已占用，自选端口 / Другой порт при занятости8080
STUDYSPACE_PORT=8082 docker compose up -d --build
```

端口仅绑定127.0.0.1。数据保存在命名卷 `studyspace_studyspace-data`，重建镜像或普通 `down` 不清空数据。不要使用 `down -v`，该命令会删除数据卷。首次构建需要网络下载依赖，构建后运行无需第三方服务。此机器已单独创建私密管理员凭据文件 `backend/data/local-admin.txt`，该文件不会上传，也不是其他克隆的默认密码。

Порт привязан только к127.0.0.1. Данные в томе `studyspace_studyspace-data`; пересборка и обычный `down` их сохраняют. `down -v` удаляет том. Для первой сборки нужен интернет, дальнейшая работа не требует внешних сервисов. Только на текущем компьютере создан приватный файл `backend/data/local-admin.txt`; он не отправляется в Git и не задаёт пароль другим клонам.

## 3 使用与规则 / Использование и правила

1. 注册本地用户名、显示名、密码并登录；无真实学号或身份审核。/ Зарегистрируйте локальный аккаунт и войдите, без номера студента и проверки вуза.
2. 选日期与时段，按校区、楼栋、楼层、类型筛选，选择空间和座位，确认预约。/ Выберите дату, интервал, фильтры, помещение и место, подтвердите.
3. 在“我的预约”筛选记录，开始前可取消；取消后立即释放座位。/ В личных записях доступны фильтры и отмена до начала; место освобождается сразу.
4. 管理员登录后出现管理工作台，可新增或软停用资源、配置日期例外、维护用户并查看统计和审计。/ После входа ADMIN доступно управление ресурсами, исключениями, пользователями, статистикой и аудитом.

上海时区、30分钟边界，默认08:00–22:00，默认含今天7个自然日（可缩小为1–7）。每条一个座位，最多24小时；同学生或同座位不能重叠，相邻或不重叠可有多条。全天24小时预约须将资源开放配置为00:00–24:00。提交时以服务器事务重新判断，查询不锁座。停用用户/资源或缩短开放时段，会自动取消受影响的未结束预约；管理员取消需原因。最后一名启用管理员受保护。

Пояс Шанхая, шаг30мин, часы08:00–22:00, окно7 дней включая сегодня (настройка1–7). Одно место, максимум24ч; пересечения студента/места запрещены, соседние интервалы допустимы. Для24ч нужны часы00:00–24:00. Сервер повторно проверяет всё в транзакции; поиск не удерживает место. Отключение и сужение часов отменяют затронутые незавершённые записи; ADMIN указывает причину. Последний активный ADMIN защищён.

## 4 备份与恢复 / Backup и восстановление

运行时每小时检查清理和当日备份，UTC日期每天至多一个快照，保留最近7份。应用停止期间不会自动备份；需要时可手动生成快照。预约终结及事件保留180天；停用30天且关联记录到期的账号匿名化。

При работе каждый час проверяются очистка и backup: один снимок в день UTC, сохраняются7. При остановленном приложении автоматической задачи нет. Записи/события хранятся180 дней, отключённый на30 дней пользователь обезличивается после истечения связей.

```bash
docker compose exec backend .venv/bin/python -m app.cli backup --output /app/backend/data/manual-snapshot.sqlite
# 恢复始终到新文件，不覆盖活动库 / Всегда новый файл, без перезаписи активной БД
docker compose exec backend .venv/bin/python -m app.cli restore --backup /app/backend/data/manual-snapshot.sqlite --output /app/backend/data/recovered.sqlite
# 原生同类操作 / Аналогично без Docker:
bash scripts/local.sh backup --output /absolute/path/to/new-snapshot.sqlite
bash scripts/local.sh restore --backup /absolute/path/to/new-snapshot.sqlite --output /absolute/path/to/recovered.sqlite
```

恢复会检查完整性、迁移、清理过期数据并撤销旧会话。检查恢复库后，先停止服务，再显式更改 `DATABASE_URL` 指向恢复文件；Compose中对应修改后重建后端。默认不自动替换当前库。`backend/data/`、数据库、备份、凭据、依赖和本机日志均排除Git。

Восстановление проверяет целостность, обновляет схему, очищает истёкшее и отзывает прежние сессии. Проверив файл, остановите сервис, явно задайте `DATABASE_URL` на восстановленную БД и пересоздайте backend. Активная БД автоматически не заменяется. БД, backup, пароли, зависимости и локальные логи исключены из Git.
